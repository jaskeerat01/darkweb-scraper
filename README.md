An automated threat intelligence collector and monitoring system for Tor hidden services. The application crawls configured onion sites, filters relevant security posts, extracts indicators of compromise (IOCs), generates threat summaries using a local language model, stores findings in a local database, and delivers real-time notifications to Telegram.

## Key Features

* **Tor Onion Service Crawling:** Monitors onion forums and marketplaces asynchronously via local Tor SOCKS5 proxy endpoints.
* **Custom Keyword Fetching from Environment:** Reads custom target keywords through the `KEYWORDS` environment variable (e.g., `KEYWORDS=data breach,exploit,crypto,leak,0day,ransomware,victim`). When `LLM_PREFILTER_KEYWORDS=true`, it screens page text for these terms prior to running inference to optimize resource consumption.
* **Local LLM Intelligence:** Uses `llama-cpp-python` with the Qwen2.5-1.5B-Instruct 4-bit quantized model for threat relevance detection and concise incident summaries without exposing sensitive intelligence to external cloud services.
* **Indicator of Compromise (IOC) Extraction:** Automatically parses cryptocurrency wallets (BTC, ETH, XMR, LTC, BCH), contact handles (Telegram, Tox, Keybase, email), and onion URLs.
* **Circuit Rotation:** Automatically signals the Tor control port to renew circuits on a periodic interval to prevent circuit stalling.
* **Duplicate Suppression & Retention:** Computes content hashes and enforces deduplication indexes in SQLite to eliminate redundant alerts while purging data older than the retention window.
* **Live Telegram Alert Dispatch:** Queues and sends HTML-formatted security alerts with automatic rate-limit backoff handling.

## Technologies Used

The engine is built on lightweight tools designed for asynchronous performance, local privacy, and low resource usage:

| Category | Technology | Purpose |
| :--- | :--- | :--- |
| **Runtime Language** | Python 3.10+ | Asynchronous event loop (`asyncio`) driving all concurrent network tasks |
| **Tor Routing & Control** | Tor Daemon, Stem, aiohttp-socks | Tor SOCKS5 proxy tunneling and automated Tor circuit renewal via the control port |
| **Asynchronous HTTP** | aiohttp | Non-blocking HTTP client for health checks and onion page downloads |
| **HTML Parsing & Scoring** | BeautifulSoup4, lxml | DOM traversal, content extraction, and heuristic relevance scoring for discovered links |
| **Local Machine Learning** | llama-cpp-python | Local inference with quantized GGUF models without sending sensitive data to third-party APIs |
| **Default Model** | Qwen2.5-1.5B-Instruct (Q4_K_M GGUF) | Relevance classification, entity recognition, and incident summarization |
| **Task Scheduling** | APScheduler | Background jobs for site health checks, periodic scraping, seed synchronization, and log cleanup |
| **Data Storage** | SQLite 3 (WAL Mode) | Persistent storage with Write-Ahead Logging and fast indexing for duplicate alert prevention |
| **Alerting** | Telegram Bot API | Asynchronous queue worker delivering formatted HTML alerts with rate-limit backoff |
| **Package Management** | Astral uv | Fast dependency resolution, virtual environment creation, and package installation |
| **Host Security** | UFW (Uncomplicated Firewall) | Local firewall lockdown restricting inbound traffic while allowing loopback and SSH |
| **Service Management** | Systemd | Background daemon supervision with automatic restarts and security sandboxing |
| **Testing** | pytest, pytest-asyncio | Unit testing for parsers, URL normalizers, and IOC extraction patterns |

## System Requirements

* **Operating System:** Ubuntu 22.04+, Debian 11+, or compatible Linux distributions
* **Privileges:** Root or `sudo` access (required for Tor configuration, package installation, and firewall rules)
* **Memory (RAM):** 
  * 4 GB minimum (for CPU-based inference with the 1.5B Q4 model)
  * 8 GB or higher recommended
* **Storage:** At least 5 GB free disk space (to store the virtual environment, GGUF model weights, and SQLite database)
* **Hardware Acceleration (Optional):** NVIDIA GPU with CUDA drivers (the installer detects `nvidia-smi` and builds GPU acceleration automatically)

## Installation

The repository includes an automated installation script (`install.sh`) that installs system dependencies, configures Tor, builds the Python virtual environment, downloads the local LLM model, sets up firewall rules, and runs the test suite.

### Step-by-step Installation

1. Clone the repository and switch to the project directory:
   ```bash
   git clone https://github.com/jaskeerat01/darkweb-scraper.git
   cd darkweb-scraper
   ```

2. Make the installer executable:
   ```bash
   chmod +x install.sh
   ```

3. Run the installer with administrative privileges:
   ```bash
   sudo ./install.sh
   ```

### What the Installer Does

During execution, the script will guide you through several prompts:

* **Tor Control Password:** Press ENTER to generate a secure random password automatically, or enter a custom string.
* **Systemd Service:** Choose whether to register and start the scraper as an automatic background daemon (`darkweb-scraper.service`).
* **Crawl Parameters:** Set the maximum link depth (default: `2`) and maximum pages to inspect per site (default: `50`).
* **Telegram Configuration:** Enter your `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` to receive live notifications. You can skip these and configure them in `.env` later.

Behind the scenes, the installer performs the following operations:
1. Installs system packages including Tor, build tools, development libraries, and Astral `uv`.
2. Configures `/etc/tor/torrc` to expose SOCKS port `9050` and authenticated Control port `9051` bound strictly to `127.0.0.1`.
3. Validates the Tor connection against the official Tor Project check API.
4. Hardens the host firewall using UFW to permit outbound traffic, loopback traffic, and SSH.
5. Creates a dedicated `.venv` virtual environment and installs all Python packages.
6. Automatically detects NVIDIA CUDA support and compiles `llama-cpp-python` with GPU offloading if available.
7. Downloads the verified Qwen2.5-1.5B-Instruct quantized GGUF model from Hugging Face into the `models/` directory.
8. Creates a protected `.env` file (permissions `0600`) pre-populated with keywords, pacing, and crawler limits, and seeds `data/forum_sites.csv`.
9. Executes the unit test suite to verify correct setup.
10. Enables and starts the `darkweb-scraper` systemd service if requested.

## Configuration

All runtime configurations are stored in the `.env` file located in the project root. A template is provided in `.env.example`.

### Primary Settings

```env
# Tor Networking
TOR_HOST=127.0.0.1
TOR_SOCKS_PORT=9050
TOR_CONTROL_PORT=9051
TOR_CONTROL_PASSWORD=your_control_password
TOR_NEWNYM_MIN_INTERVAL=10

# Telegram Alerting
TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
TELEGRAM_CHAT_ID=-1001234567890
TELEGRAM_PROXY=

# Threat Intelligence Keywords (comma-separated)
KEYWORDS=data breach,exploit,crypto,leak,0day,ransomware,victim
LLM_PREFILTER_KEYWORDS=true

# Local LLM Configuration
GGUF_MODEL_PATH=models/qwen2.5-1.5b-instruct-q4_k_m.gguf
LLM_CONTEXT=4096
LLM_THREADS=4
LLM_GPU_LAYERS=0
LLM_TEMPERATURE=0.1

# Concurrency & Pacing
MAX_PARALLEL_SITES=3
MAX_PARALLEL_FETCHES=3
MAX_PARALLEL_HEALTH=6
MAX_LLM_WORKERS=1
MAX_FETCHES_PER_DOMAIN=1

# Crawler Depth & Page Limits
PAGE_DISCOVERY_ENABLED=true
MAX_PAGES_PER_SITE=50
PAGE_DISCOVERY_DEPTH=2
MAX_LINKS_PER_PAGE=25
MIN_LINK_SCORE=-10
FOLLOW_EXTERNAL_LINKS=false
MAX_EXTERNAL_LINKS_PER_SITE=2
REQUIRE_RELEVANCE=true
THREAD_FIRST_PAGE_ONLY=true
FIRST_POST_ONLY=true
SUMMARIZE_ALERTS=true

# Storage and Target Inputs
DB_PATH=data/alerts.db
CSV_PATH=data/forum_sites.csv
DATA_RETENTION_DAYS=500
```

### Managing Target Onion Sites

Sites to monitor are listed in `data/forum_sites.csv`. You can add, edit, or remove entries at any time. The application synchronizes changes automatically without requiring a restart.

Format:
```csv
Name,Type,URL,Status,LastScrape,Uptime30,PageTitle
DarkForums,market,http://exampledarkforumonionaddress.onion/,online,08-14-26,97,DarkForums
BreachForums,market,http://examplebreachforumonionaddress.onion,online,08-14-26,97,BreachForums
```

## Database Architecture

The application persists data in SQLite (`data/alerts.db`) configured with Write-Ahead Logging (WAL) and memory optimization PRAGMAs:

* **`sites` table:** Tracks target onion URLs, group names, online status, uptime percentage over 30 cycles, consecutive failure counts, and last check timestamps.
* **`alerts` table:** Stores processed intelligence records, including source host, content hash (for duplicate prevention), threat category, extracted IOCs, entity names, full text summary, and discovery timestamp.

## Indicators of Compromise (IOC) Extraction

The engine extracts security artifacts from raw page content:

* **Cryptocurrency Addresses:** Bitcoin (Legacy, SegWit, Bech32), Ethereum, Monero, Litecoin, and Bitcoin Cash
* **Communication Channels:** Telegram channels and usernames, Tox IDs, Keybase handles, and email addresses
* **Onion Addresses:** Discovered v3 hidden service links
* **Cryptographic Keys & Hashes:** PGP key blocks, SHA-256 hashes, and related data signatures
